## Ответы на вопросы задания

### 1. Чем отличается CI от CD?

**CI (Continuous Integration)** — непрерывная интеграция: при изменении кода автоматически выполняются проверки, тесты и сборка. **CD (Continuous Delivery/Deployment)** — последующий этап доставки или развёртывания: готовая сборка доставляется для публикации (Delivery может требовать ручного подтверждения; Deployment выполняет публикацию автоматически). В этом проекте используется автоматическое развёртывание на GitHub Pages.

### 2. Что произойдёт, если тесты завершатся ошибкой на этапе CI?

Задача `ci` получит статус Failed. Следующие её шаги (сборка и загрузка артефакта) не выполнятся, задача `deploy` не начнётся, опубликованная версия сайта останется без изменений. Причину ошибки можно увидеть в логах Actions.

### 3. Для чего используется директива `needs: ci` в задаче развёртывания?

Она устанавливает зависимость: `deploy` начнёт работу только после успешного завершения задачи `ci`. При ошибке CI развёртывание будет пропущено.

### 4. Что такое артефакт и для чего он передаётся между задачами?

Артефакт — сохранённый результат сборки, в данном случае каталог `dist/` с готовой HTML-страницей, стилями, скриптом и изображениями. Задача `ci` загружает его под именем `site-build`, а задача `deploy` скачивает для публикации. Это нужно, поскольку задания выполняются на отдельных runner-машинах и не используют одну общую файловую систему.

### 5. Почему развёртывание не запускается на Pull Request?

Для Pull Request к `main` workflow выполняет проверки, но `deploy` содержит условие `if: github.ref == 'refs/heads/main'`. При событии Pull Request ссылка `github.ref` указывает на PR, а не на `refs/heads/main`, поэтому публикация пропускается. Это защищает рабочий сайт от публикации непроверенных изменений из PR.
